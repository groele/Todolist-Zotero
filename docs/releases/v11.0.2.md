# Todolist for Zotero v11.0.2

Fixes the startup errors `无法读取保存的数据: firstTimeShown` and `无法读取保存的数据: pendingTask` confirmed in the local v11.0.1 diagnostic log.

## Root cause and fix

- Welcome tips and browser context-menu startup checks still called the Chrome storage shim, which accesses `localStorage`, even in Zotero pages.
- Both calls wrapped the callback in another Promise and discarded the storage Promise. A rejected read leaked as an unhandled rejection and left the outer Promise unresolved.
- Welcome state now uses the existing `Storage` adapter and native Zotero data persistence. Its optional failure is caught and recorded.
- Zotero skips the browser-only pending-task check: Zotero context-menu commands already arrive through host navigation. Browser-mode reads await the storage Promise directly and catch failures.
- The welcome-tip timer checks that the page is still open. Persistent diagnostics now also retain a nested error's cause.

## Validation

- Before the fix, blocking browser storage reproduced both reported errors with a `SecurityError` cause. After the fix, the same probe recorded zero unhandled rejections and persisted the welcome flag successfully.
- `npm test`: 65 regression tests passed, including startup, task creation and reopen tests with browser storage forbidden in both UI pages, plus a failed welcome-flag write test.
- JavaScript syntax checks and XPI package integrity checks passed.
- Zotero 10+ remains required. Existing task data needs no migration. Original user data was read only during diagnosis.
- Desktop installation and a fresh live startup of v11.0.2 remain to be checked after updating the plugin.
